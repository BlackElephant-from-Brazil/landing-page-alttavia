**O que não existe hoje.**
- Nenhuma exclusão automática. O painel não tem botão para apagar dados de cliente: a única remoção é a de um arquivo entregue por engano. Hoje só o desenvolvedor consegue apagar, direto na base de dados e no armazenamento de arquivos. O script de limpeza (`db:purge`) só apaga contas de demonstração e de teste, mas também apaga pedidos de teste da Stripe de qualquer pessoa (o que, com o staging ligado à mesma base, pode incluir um pedido de teste de um cliente real) e, se o desenvolvedor pedir expressamente, pedidos não pagos e sem pagamento iniciado de qualquer pessoa, que podem ser de clientes reais. Com cada pedido vão os documentos, os dados, o contrato e as entregas. Ele não serve para apagar um cliente específico.
- Uma conta que terminou o formulário (tem respostas e um pedido, pago ou não) não pode ser apagada direto: a base de dados exige apagar antes os pedidos e as respostas. Dá para fazer à mão, na ordem certa, mas apagar o pedido apaga também o registro do pagamento. Para guardar esse registro, a saída é anonimizar a conta.
- Nenhuma exportação dos dados de um cliente e nenhuma ferramenta para anonimizar uma conta.
- O cliente não consegue apagar um arquivo que enviou. Arquivos recusados, versões antigas do contrato e envios interrompidos (o arquivo chegou ao armazenamento, mas a confirmação não) continuam guardados.
- As entregas também ficam sem prazo de exclusão, inclusive o arquivo "Finanças access" (o acesso do cliente ao Portal das Finanças).
- Nenhum prazo para as cópias de segurança. Nada as apaga, e apagar um dado no sistema não o apaga delas. Um cuidado: restaurar uma cópia antiga (`db:restore --apply`) devolve à base de dados as linhas que faltam de uma conta que ainda existe, então os registros de documentos e dados apagados (nome, tipo e tamanho de cada arquivo, revisão, dados das procurações) podem voltar assim. Os arquivos em si não voltam por essa via: só se alguém os enviar de novo à mão, a partir de uma cópia feita com os arquivos.
- Nenhum prazo para as notas de feedback do admin, e nenhuma opção de apagá-las. Evite colar dados de clientes no texto.
- Nenhum cookie de análise ou publicidade. O navegador guarda só o cookie de sessão e os cookies do código de acesso (`...-code-verifier`, até a saída da conta ou por até 400 dias). Na aba ficam as respostas do formulário, o email e o primeiro nome, até o pedido ser salvo. As fontes são servidas pelo próprio site.
- O Google Tag Manager existe no código, mas está desligado. Se for ligado hoje, carrega para todos os visitantes sem pedir consentimento, porque não há banner de cookies. O aviso de privacidade promete pedir antes, então ele só pode ser ligado depois de existir esse banner.
- Quem compra pela primeira vez vê os termos só como link no rodapé do formulário; o botão Pay, na área do cliente, não traz nenhuma frase de aceitação. Só a compra pela aba Services mostra "By purchasing you accept the Terms". A aceitação no Pay está prevista para quarta, 23.
- A área do cliente não tem link para nenhum texto de privacidade, embora o formulário de dados e o envio de documentos sejam onde mais dados entram.

**O que um pedido do cliente exige hoje.**
- Acesso ou cópia: o painel mostra perfil, respostas, dados das procurações, contrato e arquivos, e você baixa um arquivo por vez. Não há exportação. Uma cópia completa, com os registros de acesso, sai da base de dados pelo desenvolvedor.
- Correção: o cliente corrige os dados das procurações na área dele enquanto houver uma procuração assinada por enviar (o botão volta depois de uma recusa). Depois disso, ou para nome e email, só o desenvolvedor, direto na base de dados; o painel não edita esses dados. Se o contrato já saiu, é preciso regenerá-lo no admin.
- Exclusão: o desenvolvedor apaga os arquivos do pedido no armazenamento, os pedidos, as respostas e a conta, e depois as cópias no computador dele. Fora da plataforma ficam os dados na Stripe (conta da firma), os emails (caixa do cliente, caixas da firma e o registro da Resend) e os logs do servidor na Netlify, cada um com o seu prazo.
- O aviso promete resposta em um mês. Vale combinar quem faz o quê antes do primeiro pedido.
